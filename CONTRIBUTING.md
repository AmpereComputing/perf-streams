# Contributing

We appreciate any/all contributions! However, contributions must:

* Take into account existing implementations and potential
  backwards-compatibility (especially for protobufs)
* Extend existing tools or capabilities; larger contributions that add
  completely new tools may be better suited for a separate repository
* Any larger changes (i.e. new features vs. small bugfixes) should be discussed
  with the maintainers prior to beginning implementation. This helps everyone
  align on direction and avoid wasted effort.

## PR Requirements

* Clearly describe the motivation for the change and what it does
* Be as concise as possible, splitting changes into separate commits is helpful
  for understanding
* Reference any issues that are fixed or related

## Code Requirements

Most of these are enforced by CI in the PR, but specifically:

* All tests must pass
* Code must meet style/formatting guidelines

## AI Labeling Requirements

Any code modifications made by AI agents should be labeled as such, ideally in
a git commit message *and* in the code. Labeling via git messages is
*absolutely* required.

For git messages, use the following message:

    Assisted-by: <AGENT_NAME>:<MODEL_VERSION>

For source comments, if a file/class is added with AI, there should be a
comment indicating so, in the following format:

    Assisted and/or generated by <AGENT_NAME>:<MODEL_VERSION>

Comments can be grouped semantically by block/function/class/file, etc.
Per-line labeling is *not* required.
